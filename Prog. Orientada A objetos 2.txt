Polimorfismo

Override = Redefine comportamento de método herdado.

Overload = Vários métodos com mesmo nome, porem parâmetros diferentes.

public int Somar(int a, int b) {
     return a + b;
}

1. Override (Sobrescrita)

Acontece quando uma classe filha redefine um método da classe pai.

Exemplo:

class Animal {
    public void emitirSom() {
        System.out.println("Som genérico");
    }
}

class Cachorro extends Animal {
    @Override
    public void emitirSom() {
        System.out.println("Au Au");
    }
}

2. Overload (Sobrecarga)

Acontece quando existem vários métodos com o mesmo nome, mas com parâmetros diferentes.

Exemplo:

public class Calculadora {

    public int somar(int a, int b) {
        return a + b;
    }

    public int somar(int a, int b, int c) {
        return a + b + c;
    }

    public double somar(double a, double b) {
        return a + b;
    }
}

Aqui o compilador escolhe qual método usar antes do programa executar, olhando para os parâmetros.

Exemplo:

Calculadora calc = new Calculadora();

calc.somar(2, 3);         // chama o primeiro
calc.somar(2, 3, 4);      // chama o segundo
calc.somar(2.5, 3.5);     // chama o terceiro

Performance e alocação eficiente

Pontos importantes:
	quanto tempo o código leva para executar
	quanto ele aloca de memória durante a execução

um código que executa milhares(ou milhões) de operações precisa ser especialmente tratado.

alocação

alocar memória significa reservar um espaço na memória do computador para guardar uma informação.

por ex:
	int idade = 30; -> o programa precisa de memória para armazenar o 30.

essa reserva é uma alocação: o ato de reservar memória para que um dado 
possa existir durante a execução de um programa.

O problema das alocações:

alocar memória tem custo.

for(int i = 0; i< 1000000; i++ {
	Cliente C = new Cliente();
}

estamos pedindo ao sistema para criar 1 milhão de objetos e armazená-los durante o tempo de execução

Garbage collector

cliente c = new cliente() -> cria na memoria

cliente = null -> objeto não é mais utilizado, mas o espaço não precisa ser liberado imediatamente.

O .NET possui o GC que identifica objetos que não estão mais em uso e recupera memória.

alocação -> obj utilizado -> obj deixa de ser executado ->  GC identifica -> memoria liberada.

quando criamos muitos obj, há mais trabalho para o GC e mais "pressão" sobre a memória.


Span <T>

é uma forma de enxergar uma região da memória sem precisar criar uma nova coleção

Ex:
	int[] números = {10,20,30,40,50}
	span<int> parte = números.AsSpan(1,3);
	
teremos:

array original {10,20,30,40,50} ->  Span<int> 20 30 40

O ponto importante: parte não representa um novo espaço alocado na memoria:
o span é apenas uma "janela" sobre os dados existentes

ex:

string texto ='abc1234';

queremos pegar 123

string parte = texto.substring(3,3);

AULA 5

Pading

Estratégia para redução de alocações.

Significa reutilizar objetos já alocados, em vez de criar e destruir novos objetos,
evitando alocações repetidas.

Contexto, exemplo, upload de arquivo de 2GB.

Se enviarmos um arquivo de 2GB a um servidor, ele não precisa ter 2GB de RAM disponíveis

File 2GB -> RAM -> DISCO

Normalmente o server recebe o arquivo progressivamente, em pequenos "Pedaços".

Recebe 64KB e grava disco -> recebe 64KB e grava no disco....

Tipo primitivo byte

byte valor 100;
byte representa um valor de 0 a 255.
byte[] buffer = new byte[64 * 1024];

temos um array com espaço para 64KB.

buffer: é uma área temporária de memoria usada para armazenar dados enquanto eles estão sendo transferidos ou processados.

O problema da alocação(de novo)

Se o servidor receber vários uploads simultâneos, cada operação cria um buffer, reservando espaço na memoria.

mais alocação -> mais trabalho para o GB -> menor performance.

sem pading 

Criar -> Usar -> descartar
criar -> usar -> descartar...


Se isso acontece milhares de vezes, temos muitas alocações 

Com pading

o buffer é criado uma vez e depois é reutilizado

ArrayPool <t>

byte[] buffer = ArrayPool<byte>.Shared.Rent(64*1024);
try {
	//uso
} finally {
	ArrayPool<byte>.Shared.Return(buffer);
}

Rent() pega um array disponível no pool.
Return() devolve o array para que possa ser reutilizado.
