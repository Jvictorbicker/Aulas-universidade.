Aula 4

Cursores 

* Por padrão, o SGBD Relacional trabalha como conceito de conjutos 
ou self-based.

* Quando é executado com SELECT, o motor de BD processa e devolve todas
as linhas de uma vez só

* Um cursor quebra em paradigma permitindo que o banco mude para o modelo
iterativo ou Row-by-Row

* Funciona como um ponteiro logico que navega pelo resultado de uma consulta,
permitindo que seja processado uma linha por vez.

Para que serve?

* Regras de negocio linha a linha: quando a regra de um registro depende de cálculo complexo
que variam a cada linha 

ex: calcular o saldo devedor histórico de um cliente com base de dados

* processamentos procedures sequenciais: disparar ações externos ou rotinas customizadas 
para cada registro encontrado.

ex: rodar o processamento da folha de pagamento enviando uma requisição por funcionário

* integrações e migrações: varredura de dados antigos para tratamento ou auditoria
antes de mover para outra tabela.

Importante

* O processamento linha por linha é muito mais pesado que o processamento em conjunto

* Cursores devem ser usados com sabedoria, apenas quando comandos SQL tradicionais 
(UPDATE, INSERT) não forem suficientes.

* Ciclo de vida

1) DECLARE CURSOS: associar o cursor a uma instrução SELECT. É aqui que definimos quais dados serão varridos
2) OPEN: Executa a consulta vinculada e popular o cursor na memoria do servidor.
 O ponteiro e posicionado logo antes da primeira linha
3) FETCH NEXT avança o ponteiro para a próxima linha disponível e extrai seus valores,
copiando para variáveis locais
4) CLOSE: fecha o cursor ativo. ele limpa os dados da memória, mas mantém a estrutura de cursor disponível
caso seja necessário abrir(open) novamente.
5) dealocate, destrói definitivamente a estrutura do cursor.
					(YES)
DECLARE -> OPEN -> FETCH  -> IS EMPTY -> CLOSE -> DEALOCATE  
				(no)  |
				      V
				    FETCH
variável global de controle
-> @@FETCH_STATUS
retorna o status do ultimo comando fetch executado

0: executou com sucesso e uma linha for retornada
-1: comando falhou ou o cursor chegou ao fim do conjunto de dados
-2: a linha buscada foi deletada ou indisponível

DECLARE @nomecidade VARCHAR(100),
DECLARE @siglaestado varchar(2),

DECLARE cursor_cidade CURSOR FOR
	SELECT C.cidnome, UF.ufsigla
	FROM CIDADE C, UNIDADE_FEDERATIVA UF
	WHERE C.ufsigla = UF.ufsigla
	OPEN cursor cidade;
	
	FETCH NEXT FROM cursor cidade INTO @nomecidade, @siglaestado
	WHILE @@fetch_status = 0
	BEGIN
	PRINT 'cidade: ' + @nomecidade + 'estado: ' + @siglaestado;
	FETCH NEXT FROM cursor_cidade INTO @nomecidade, @siglaestado;
	END
CLOSE cursor cidades;
DEALLOCATE cursor cidades;

cursores aninhados

* Um cursor aninhado é a forma técnica de declarar e executar um cursor(filho) dentro
do bloco de execução de outro cursor

-essa abordagem é utilizada sempre que precisamos resolver regras de negocio que envolvem
relacionamento 1 para N, onde queremos tratar o registro principal e processar seus registros
dependentes.

ex:

	estado -> cidades
	cliente -> pedidos
	pedidos -> lista de produto


DECLARE @idcliente INT, @Nomecliente VARCHAR(100);
DECLARE @numpedido INT, @valorpedido decimal(16,2);
DECLARE @totalgeralcliente DECIMAL(16,2);

DECLARE cursor_para_clientes CURSOR FOR 
	SELECT clientecod, clientenome
	FROM CLIENTE;
OPEN cursor_para_clientes
FETCH NEXT FROM cursor_para_clientes INTO @idcliente, @nomecliente;

WHILE @@FETCH_STATUS = 0
BEGIN
	PRINT 'cliente: ' + @nomecliente;
	SET @totalgeralcliente = 0.00;

	DECLARE cursor_filho_pedidos CURSOR FOR
		SELECT P.pedidonum, P.pedidovalortotal
		FROM PEDIDO P
		WHERE P.clientecod = @idcliente
	OPEN cursor_filho_pedidos;
	FETCH NEXT FROM cursor_filho_pedidos INTO @numpedido, @valorpedido;
	BEGIN
		PRINT 'pedido: ' + CAST(@numpedido as VARCHAR) +
		'valor: ' + CAST(@valorpedido AS VARCHAR);
		SET @totalgeralcliente = @totalgeralcliente + @valorpedido
	END

CLOSE cursor_filho_pedidos;
DEALLOCATE cursor_filho_pedidos;
PRINT 'total acumulado ' + CAST(@totalgeralcliente AS VARCHAR);
END

CLOSE cursor_para_clientes;
DEALLOCATE  cursor_para_clientes;
